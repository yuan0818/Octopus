# 项目背景与 LLM 步骤补全

在「业务 API 测试 → 项目背景」选择已经分析的项目，维护业务职责、业务约束、测试环境 URL，以及 MySQL / PostgreSQL / MongoDB / Redis / Kafka / RabbitMQ / Elasticsearch 等依赖信息。接口资产选中项目或模块后，也可以直接进入相应的背景配置。

- 背景身份是 `repositoryKey + modulePath + environment`。项目默认配置使用空 modulePath，根目录源码模块使用 `.`。相同模块在不同代码分支/分析批次中复用背景；环境使用独立标识，如 `test`、`staging`。
- 模块业务背景与项目背景合并；模块 URL 留空时继承项目 URL。连接按稳定 ID 继承，点击「在模块中覆盖」后由模块配置替代整个连接。不同项目不会按名称合并。
- 运行已确认的测试场景时，点击「使用已保存的测试地址」，按场景中固定 API 实现所属项目/模块填入环境 URL。若同一服务键出现多个地址，会提示人工选择。
- 保存背景或生成草稿不会建立网络连接。MySQL、PostgreSQL、Redis、Kafka 连接可以在接口步骤中添加自然语言生成的数据验证，确认 Flow 后通过 [JMeter 扩展](../octopus-jmeter-ext/README.md) 执行；其他连接仍作为背景资产保存。

## 凭据

用户名和密码通过独立字段写入，复用 `CredentialEncryptor` 进行 AES-GCM 加密，保存在 `business_project_context.credentials_encrypted`。描述性配置与密文分列保存；读取接口只返回凭据是否存在，编辑时留空保留、勾选清除才删除。删除连接同时删除该连接在本层的凭据。

设置稳定的 `OCTOPUS_ENCRYPTION_KEY`（16/24/32 个 UTF-8 字节），或覆盖 `scenario.testing.encryption-key`。密钥未配置时，只允许保存无凭据的背景，不会降级为明文存储。密钥应在服务配置中管理并备份；此功能不提供自动换钥迁移。凭据值不写入模型输入、Flow、Test IR 或 JMX。

LLM 背景投影仅包含业务描述、约束、环境标识和连接的名称、类型、用途。主机、URL、数据库实例和凭据字段不进入模型背景。请将认证信息填入独立凭据字段，勿写入业务描述、用途或业务目标文本。

## 人编排路径，LLM 补全步骤

「创建业务流程」直接进入画布。人先选择精确版本的 API、安排顺序或分支并确定测试点，然后点击「逐步 AI 补全」。从项目背景进入时，接口选择器继承项目/模块范围。接口资产的项目、模块、分支及提交筛选保持不变。

面板按已规划的依赖顺序逐个处理节点，也可手动切换。每次请求只包含当前节点的精确 API 契约、该提交的源码片段、项目与模块背景、普通预置数据，以及依赖链上已确认且仍有效的步骤记忆。流程名称、节点名称、HTTP 路径与依赖只用来说明人工规划的目标，不把其他 API 的契约、源码或整个目录交给模型。模型复用 review-agent 的已有配置。

源码按项目、分支、完整提交和方法签名读取，当前支持 Java 入口方法、可解析的直接返回方法及相关 DTO。每次最多 20 段、48,000 字符；保留文件、行号和提交作为依据。字符串常量与注释经过脱敏，DTO 方法体省略。完成下述仓库背景分析后，同版本网关过滤器和公共组件归纳会自动纳入；动态配置及完整跨服务调用仍需确认，缺失范围随记忆传递。“Controller 没有声明 token Header”不能推导为“入口无需鉴权”。

模型只返回当前节点的增量补丁 `node{id,inputs,outputs}`、该节点新增的 `assertions`、`assumptions/questions` 和 `memory{summary,decisions,questions,evidenceIds}`。已有输入默认保留，勾选后才允许重填。其他节点、接口、顺序、依赖、状态模型、测试点覆盖值和已有业务断言不能改变。上下文只能引用预置变量或既定上游输出，全流程生产者唯一性与既定执行顺序仍会校验。

服务端拒绝越界端口、不匹配类型、重复生产者、未知响应路径、越界字段和未声明的结构化请求字段。未知或复杂到无法确定的契约需由用户补充，不臆造数据。最多 50 个已选步骤；模型输出不合法或不可用时保留原草稿并显示错误。

补全面板支持声明预置变量并填写普通测试值。变量声明随草稿保存；值仅在当前页面内存中保存，带入相同环境的运行配置，刷新后需重新填写，不持久化到 Flow/IR/JMX。敏感变量仅提供名称和类型，敏感值仍在运行时填写。切换参考环境清空预置值。模型使用 `source=context` 建立引用，而非把预置数据固化成字面量。

生成后展示当前节点的变化及记忆草稿。点击「应用并继续下一步」才应用当前节点，同时确认保存其记忆，再读取下一节点；不会连续自动调用模型。如果没有可填字段，仍可确认保存有依据的记忆和待解决问题。应用不会自动保存或确认整个 Flow，也不调用测试 URL 或数据库；离开面板后仍需保存流程草稿。

## 整条链路自动补全

画布的主入口为「AI 补全整个链路」；选择接口后「加入并 AI 补全」也进入整链任务。原来的逐节点面板保留在「补全单个步骤」。

一次点击「开始整链补全」后，由服务端任务按人工依赖图的拓扑顺序逐节点推进；不会一次让模型处理整个目录或同时重规划所有节点。每一步经过 `WAITING → PREPARING → GENERATING → COMPLETED`，分别对应等待、读取上下文、模型补全和候选建议生成。失败节点进入 `FAILED`，后续节点停止。

任务状态包括排队、运行、请求暂停、已暂停、失败、全链建议待审、应用中、已应用及取消。暂停会等待当前节点完成；继续或失败重试从尚未完成的节点接着推进。可以在暂停、失败或全链待审时，选择「从此节点重新生成后续链路」：恢复该节点之前的候选快照，清除从该节点开始的候选记忆与结果，再沿既定依赖顺序生成。取消后的迟到模型响应不进入任务结果。

工作区保存独立的原始 Flow 和候选 Flow。后续节点使用本次任务已经生成的祖先输出及 `WORKING` 记忆；这些候选记忆仍在数据库中保持 `PENDING`，不能被其他补全任务自动当作已确认知识。模型会收到明确的候选标识，必须延续未解决问题而非把它们当作业务真相。全部节点生成后，用户统一审阅变化、记忆和问题；「统一应用」先校验整条链路及当前背景，再在事务中确认所有记忆。只有此时画布才应用候选 Flow，仍需保存草稿、确认业务预期后才能进入测试执行。

画布发生修改时禁止旧任务覆盖。任务请求使用幂等请求标识，同一 Flow 只能有一个未结束的任务；进度响应带递增 revision，前端不会用迟到的旧状态覆盖新状态。关闭面板不会停止任务，重新打开会连接该 Flow 的当前任务。

任务、原始及候选 Flow、每个节点之前的检查点、候选记忆引用、预置参考值和最近 200 条运行事件写入 MySQL `business_flow_chain`。快照使用现有 `OCTOPUS_ENCRYPTION_KEY` 进行 AES-GCM 加密，未配置密钥时拒绝创建任务，不降级为明文。单个快照上限 8 MB；不保存整段源码或模型请求/响应原文。GET 任务接口不回显预置参考值。模型调用使用两个工作线程和有界队列。

执行器每 5 秒续约，租约 45 秒。进程正常退出时立即把正在执行的任务标为可恢复暂停；进程崩溃或数据库失联导致租约过期时，后台巡检在到期后约 5 秒内恢复到最近检查点。中断节点进入 `INTERRUPTED`，已完成节点保持不变；用户点击继续后只重新生成尚未完成节点。数据库行锁、任务执行令牌和有效租约共同阻止并发推进及旧执行器的迟到写入。尚未启动的持久排队任务可以被服务重新接管。

侧栏「AI 补全任务」进入 `/business-testing/tasks`，集中查看最近更新的 100 个整链任务（含已取消），按流程名称、节点、任务 ID、环境和状态筛选。列表每 5 秒同步，展示节点进度、当前步骤、创建/更新时间、失败原因和处理建议；可暂停、从检查点继续，或进入详情查看候选变化、源码依据、步骤记忆与错误历史。详情与筛选可通过 URL 直接恢复，模型补全面板也有「在任务中心查看」入口。列表读取失败保留上次结果并自动重连。

查看任务详情不会替换正在编辑的画布；明确打开任务的流程草稿时，先检查未保存改动。已确认任务仍可找回候选结果；确认接口可安全重放。统一确认步骤记忆和保存任务 `ACCEPTED` 状态使用同一个事务，发生故障时一起回滚，不会出现半条链路被确认。恢复草稿不等于保存业务 Flow。

失败记录包含失败阶段、节点、错误类别、上游 HTTP 状态（如有）、发生时间、处理建议和可复制的诊断编号。模型超时、限流、认证/配置错误、连接失败、无效 JSON、契约校验失败、上下文过期、执行中断和检查点存储错误分别展示；原始异常、上游响应正文、凭据和模型提示不进入错误日志或页面。成功重试后仍保留错误历史。补全模型请求每次只调用一次，由状态机显式管理重试，不再隐式重试或切换模型。

恢复保证已提交检查点不被重复应用，不保证模型调用恰好一次：进程可能在模型返回后、检查点写入前崩溃，重试会重新调用该节点，原调用可能已经计费。模型产生但未进入检查点的记忆保持未确认，不参与恢复。任务存储需与数据库和加密密钥一起备份；此前仅驻留内存、从未持久化的旧任务无法凭空恢复。

整链 API（前缀 `/api/business-testing/flow-suggestions/chains`）：

- `POST /`：requestId、flow、environment、goal、model、contextValues；立即返回任务。
- `GET /?flowId=...`：该 Flow 当前任务；`GET /{id}`：当前状态、节点结果及候选 Flow。
- `GET /recoverable`：最近 50 个未取消任务的摘要，包含未保存 Flow 和已确认结果，供刷新后恢复。
- `GET /tasks`：最近更新的 100 个任务摘要，包含取消历史、节点进度与当前节点；不返回源代码、候选 Flow 或预置参考值。
- `POST /{id}/pause`、`/resume`、`/cancel`：控制推进。
- `POST /{id}/retry`：传 nodeId，从该节点重新生成后续链路。
- `POST /{id}/confirm`：传 originalHash/resultHash，确认本次完整候选及记忆；不保存或执行 Flow。

## 仓库级入口背景分析

在「项目背景」选择仓库、分支、提交与环境，点击「分析仓库背景」。当前模块筛选不限制仓库范围。

分析流程为目录读取 → 模型规划 → 分项读取源码与记忆 → 汇总全部记忆。每个模块必须分配到分析项，最终报告必须覆盖全部任务和模块。模型按目录决定读取文件，不再按固定类名规则采集。计划与各项记忆均持久化，失败从检查点继续；总结失败不会重做已完成的模块分析。源码覆盖缺口、截断及不支持文件类型会明确展示。

报告仍按仓库、分支、提交、环境隔离。旧报告兼容保留，步骤补全使用对应版本报告，报告变化会使相关候选记忆过期。人工背景优先，静态源码结论不能替代部署配置或人工业务预期。

接口、预算与安全读取器范围见 [仓库分析编排说明](REPOSITORY_ORCHESTRATION.md)。

## 步骤记忆

`business_step_memory` 持久化每次生成的候选记忆，初始为 `PENDING`。应用时校验完整候选 Flow 的摘要及当前背景版本，成功后变为 `CONFIRMED`。跨任务只复用已确认记忆；整链任务内部通过服务端检查点引用自己的上游候选，以 `WORKING` 标识传递。

记忆保存步骤作用、映射理由、变量名称和提取路径、源码依据及未解决问题；不保存整段源码、运行结果或连接凭据。普通预置字符串若被模型复述，会在记忆落库前省略。模型归纳与人工业务规则分开，不能把实现行为直接当作正确性依据。

记忆绑定 Flow、节点和环境，指纹涵盖当前节点与所有祖先的 API 版本、输入、输出、检查项、相关依赖、初始变量声明以及背景配置版本。重读面板时不匹配的记忆显示「已过期」且不发送给模型。改下游不会使上游记忆失效，改上游会使受影响的下游记忆失效。相同配置的已确认历史记忆可复用；运行时测试值不属于记忆事实。

SQL、Redis、Kafka 的数据验证仍使用步骤内独立的验证编辑器，由人选择连接、明确业务预期，再生成并确认计划。

## 服务与迁移

- 场景服务：`GET/PUT /api/business-testing/contexts`、`GET /contexts/environments`、`POST /contexts/execution-defaults`；`GET /flow-suggestions/models`、`POST /flow-suggestions`（均位于 `/api/business-testing` 下）。
- 单节点接口（场景服务）：`POST /api/business-testing/flow-suggestions/steps/prepare`（flow/nodeId/environment），`POST /steps`（另带 goal/model/contextValues/editableInputs），`POST /steps/confirm`（memoryId/flow/environment）；后两者使用同一 `/api/business-testing/flow-suggestions` 前缀。单步面板使用这些接口；整链面板通过任务接口由服务端逐节点调用，旧整条流程接口保留兼容。
- 源码接口（查询服务）：`GET /api/query/endpoint-contract/source-context`。
- Agent 单节点接口：`POST /api/business-flow/step-suggest`。
- Agent 服务：`GET /api/business-flow/models`、`POST /api/business-flow/suggest`。
- 对已有数据库执行 `src/main/resources/db/business-testing.sql` 中新增的 `business_project_context`、`business_step_memory`、`business_flow_chain` 和 `business_repository_analysis` 建表语句，或启动时使用 Spring SQL 初始化加载该幂等脚本；生产默认不自动建表。
- 本功能使用现有服务的访问边界，没有新增登录或权限系统。与其他内部服务一样，部署时应通过现有网关和网络访问控制限制配置接口。
