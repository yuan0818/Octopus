## 第一步：生成测试代码（6 个测试类）

按照项目已有的测试规范（JUnit 5 + Mockito + `@ExtendWith(MockitoExtension.class)`），为以下核心组件编写单元测试：

### 1. `SchemaValidatorTest`（octopus-review-agent）
- 正常校验通过
- issues 为空/null 抛 SchemaValidationException
- severity 枚举非法抛异常
- severity 兼容映射（HIGH→BLOCKER, MEDIUM→WARNING, LOW→INFO）
- category/description 缺失抛异常
- requirementChecks 校验
- response 为 null 抛异常
- 所有合法 severity 枚举值

### 2. `SkillExecutorTest`（octopus-review-agent）
- 首次校验通过 → 直接返回成功
- 校验失败 → 重试后通过
- 重试耗尽 → 返回 category=SYSTEM 的诊断 ReviewResponse
- LLM 调用失败 → 重试后仍失败 → 兜底响应
- Skill validation 失败 → 返回 failure

### 3. `GitSourceProviderTest`（octopus-code-reconstruct）
- extractLines 正常行号提取
- extractLines 边界行号（0, 超出范围）
- extractRepoName 从各种 URL 格式提取仓库名
- commitId 为空返回 notFound
- filePath 为空返回 notFound

### 4. `VersionCleanupServiceTest`（code-intelligence）
- 清理逻辑正确执行（mock DataSource/Connection/PreparedStatement）
- SQL 异常时优雅降级
- Unknown column 异常时的 warn 处理

### 5. `LookupControllerTest` 扩展（octopus-review-agent）
- listClasses 带 branch/commitId 参数
- listMethods 带 branch/commitId 参数

### 6. `QueryServiceTest` 扩展（code-intelligence）
- getEndpoints 带 branch/commitId 参数
- getEntryPoints 带 commitId 的测试
- versionFilter 逻辑验证
